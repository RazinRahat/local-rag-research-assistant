# Local RAG Research Assistant

A local-first research assistant for querying and analysing research documents using Retrieval-Augmented Generation (RAG).

The project is being built component by component to explore the engineering behind document processing, semantic retrieval, local language generation, context construction, grounded answers, citations, and RAG evaluation without hiding the core pipeline behind a high-level RAG framework.

## Current Status

**Phase 8 complete — validated citations and inspectable source evidence.**

```text
Research PDF
     ↓
Page Extraction & Normalisation
     ↓
Model-Aware Chunking
     ↓
Local Embeddings
     ↓
Persistent Vector Store (Qdrant)
     ↓
Semantic Retrieval
     ↓
Bounded Context Construction
     ↓
Local LLM (Ollama / Qwen)
     ↓
RAGResponse with [S1], [S2], ...
     ↓
Citation Parsing & Validation
     ↓
CitedRAGResponse
     ↓
RAG API                         ← next
```

The system can ingest and index research PDFs, retrieve semantically relevant evidence, construct a token-bounded context, generate a local answer, and verify that the answer's **recognised citation references** point only to evidence supplied to the model. Formal claim-to-source support evaluation remains future work.

## Current Features

- PDF validation, page-level extraction, metadata, and conservative normalisation
- SHA-256 document identity and page-level provenance preservation
- Typed document and chunk models; encrypted/non-text PDF handling
- Configurable token-aware, model-aligned chunking with deterministic IDs
- Local BGE document/query embeddings, normalisation, and batched inference
- Persistent Qdrant vectors, chunk text, and provenance payloads
- Collection compatibility checks, document replacement, and deletion
- Dense semantic retrieval with top-k, optional thresholds, and document filtering
- Typed and ranked retrieval results
- Local Qwen generation through an Ollama-backed `LLMProvider`
- Configurable context and output limits, token counts, and inference timings
- Explicit context budgeting and chat-template-aware token estimation
- Whole-chunk evidence selection, order preservation, and redundancy filtering
- Grounding instructions and source-labelled evidence delimiters
- No-evidence response without invoking the LLM
- Typed `RAGResponse` exposing selected evidence and generation diagnostics
- Strict `[S1]`, `[S2]`, … inline citation protocol
- Citation parsing with character offsets and unique-source mapping
- Rejection of unknown source identifiers and missing citations in evidence-backed answers
- Source metadata recovered from trusted `EvidenceBlock` provenance, not generated by the model
- Typed `CitedRAGResponse` with distinct inline references and cited sources
- Strict type checking, automated unit tests, and real local smoke-testing workflow

## Architecture

The current implementation is a complete local dense-RAG baseline with a separate citation-integrity layer:

```text
Research PDF ──→ Ingestion ──→ Chunking ──→ Embeddings ──→ Qdrant
                                                           │
User Question ──→ Query Embedding ──→ Semantic Retrieval ←───┘
                                         │
                                         ▼
                                   Ranked Evidence
                                         │
                                         ▼
                                   Context Builder
                          ┌──────────────┼──────────────┐
                          ▼              ▼              ▼
                    Token Budget    Deduplication   Source Labels
                          └──────────────┼──────────────┘
                                         ▼
                                  Grounded Prompt
                                         │
                                         ▼
                                   Ollama / Qwen
                                         │
                                         ▼
                                    RAGResponse
                                         │
                                         ▼
                              Citation Parser & Validator
                                         │
                                         ▼
                                   CitedRAGResponse
                                ┌────────┴────────┐
                                ▼                 ▼
                       Inline References   Validated Sources
                                                 │
                                                 ▼
                                        Document / Page / Chunk
```

Each validated citation resolves to an `EvidenceBlock` selected for the corresponding prompt. The model selects a temporary source key; the application owns the document, page, and chunk metadata. Citation identity validation **does not yet establish semantic entailment** for every cited claim.

See [System Architecture](docs/architecture.md), [End-to-End RAG Pipeline](docs/rag-pipeline.md), and [Citations](docs/citations.md).

## Development

Install dependencies:

```bash
poetry install
```

Run the existing FastAPI development server (the complete RAG endpoints are planned for Phase 9):

```bash
poetry run uvicorn research_assistant.main:app --reload --app-dir src
```

Run the quality gate:

```bash
poetry run ruff check .
poetry run ruff format --check .
poetry run mypy
poetry run pytest
```

## Local Model Runtime

The generation baseline uses a local Ollama model. Ensure Ollama is installed and running, then:

```bash
ollama pull qwen3.5:9b
ollama list
```

Model files are managed outside this repository and are not committed to Git.

## Local Documents and Data

Research documents belong in `data/documents/`; the persistent vector store is created under `data/vector_store/`. These paths, environment files, and local model artifacts are excluded from version control. The Qdrant payload contains source text and metadata, so the vector store should be treated as potentially private data, not merely disposable cache.

## Roadmap

**Completed:** Project foundation, PDF ingestion, token-aware chunking, local embeddings, persistent vector storage, semantic retrieval, local LLM integration, end-to-end RAG orchestration, and citation integrity.

**Next:** RAG API: document ingestion/indexing, document management, semantic search, cited query responses, lifecycle management, and error handling.

**Later:** User interface, hybrid retrieval, reranking, RAG evaluation/benchmarking, research-specific synthesis, observability, containerisation, and reproducible deployment.

## Design Principles

- **Local first:** keep research documents, vectors, retrieval, and inference local where practical.
- **Preserve provenance:** trace retrieved material and cited evidence back to original pages.
- **Understand before abstracting:** implement inspectable mechanics before high-level RAG frameworks.
- **Separate responsibilities:** parsing, embeddings, storage, retrieval, context construction, generation, and citations remain testable boundaries.
- **Bound the context:** allocate evidence within explicit model and output budgets.
- **Treat retrieved text as data:** never promote document content into application instructions.
- **Validate model output:** only application-known source IDs may appear as validated citations.
- **Measure instead of guess:** benchmark retrieval, citation behaviour, grounding, and runtime performance before claiming effectiveness.

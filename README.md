# Local RAG Research Assistant

A local-first research assistant for querying and analysing research documents using Retrieval-Augmented Generation (RAG).

The project is being built component by component to explore the engineering behind document processing, semantic retrieval, local language generation, context construction, grounded answers, citations, APIs, and RAG evaluation without hiding the core pipeline behind a high-level RAG framework.

## Current Status

**Phase 9 complete — the local RAG pipeline is exposed through a typed FastAPI application layer.**

```text
Research PDF
     ↓
POST /documents
     ↓
Page Extraction & Normalisation
     ↓
Model-Aware Chunking
     ↓
Local Embeddings
     ↓
Persistent Vector Store (Qdrant)
     ↓
Semantic Retrieval
     ↓
Bounded Context Construction
     ↓
Local LLM (Ollama / Qwen)
     ↓
RAGResponse with [S1], [S2], ...
     ↓
Citation Parsing & Validation
     ↓
CitedRAGResponse
     ↓
FastAPI JSON Response
```

The system can ingest and index research PDFs, enumerate and delete indexed documents, perform semantic search, construct token-bounded evidence contexts, generate local answers, validate recognised source references, and expose the complete workflow through HTTP endpoints.

Citation identity validation confirms that recognised `[S#]` references resolve to evidence actually supplied to the model. It does **not yet establish semantic entailment** between every generated claim and its cited passage.

## Current Features

- PDF validation, page-level extraction, metadata, and conservative normalisation
- SHA-256 document identity and page-level provenance preservation
- Typed document and chunk models; encrypted/non-text PDF handling
- Configurable token-aware, model-aligned chunking with deterministic IDs
- Local BGE document/query embeddings, normalisation, and batched inference
- Persistent Qdrant vectors, chunk text, and provenance payloads
- Collection compatibility checks, document replacement, deletion, and document enumeration
- Dense semantic retrieval with top-k, optional thresholds, and document filtering
- Typed and ranked retrieval results
- Local Qwen generation through an Ollama-backed `LLMProvider`
- Configurable context and output limits, token counts, and inference timings
- Explicit context budgeting and chat-template-aware token estimation
- Whole-chunk evidence selection, order preservation, and redundancy filtering
- Grounding instructions and source-labelled evidence delimiters
- No-evidence response without invoking the LLM
- Typed `RAGResponse` exposing selected evidence and generation diagnostics
- Strict `[S1]`, `[S2]`, … inline citation protocol
- Citation parsing with character offsets and unique-source mapping
- Rejection of unknown source identifiers and missing citations in evidence-backed answers
- Source metadata recovered from trusted `EvidenceBlock` provenance, not generated by the model
- Typed `CitedRAGResponse` with inline references and validated sources
- FastAPI endpoints for document management, semantic search, and cited RAG queries
- Lazy runtime composition for local models and persistent infrastructure
- Explicit application lifecycle for Ollama and Qdrant resources
- Request validation and domain-to-HTTP error translation
- Strict type checking, automated unit tests, regression testing, and real local smoke-testing workflows

## Architecture

The current implementation exposes the complete local dense-RAG baseline through an HTTP application boundary:

```text
                           Client
                              │
                              ▼
                           FastAPI
                              │
                  ┌───────────┼───────────┐
                  │           │           │
                  ▼           ▼           ▼
             Documents      Search       Query
                  │           │           │
                  ▼           ▼           ▼
            ResearchService / ResearchAPI
                  │           │           │
        ┌─────────┘           │           └──────────┐
        ▼                     ▼                      ▼
 LocalPDFIndexer       SemanticRetriever        RAGService
        │                     │                      │
        ▼                     ▼                      ▼
   PDF Ingestion          Query Embedding       ContextBuilder
        │                     │                      │
        ▼                     ▼                      ▼
     Chunking             Qdrant Search          Ollama/Qwen
        │                                            │
        ▼                                            ▼
    Embeddings                                  RAGResponse
        │                                            │
        ▼                                            ▼
      Qdrant                                  CitationService
                                                     │
                                                     ▼
                                              CitedRAGResponse
```

### Indexing path

```text
POST /documents
      ↓
LocalPDFIndexer
      ↓
PyMuPDF ingestion
      ↓
model-aware chunking
      ↓
BGE embeddings
      ↓
Qdrant
      ↓
StoredDocument
```

### Query path

```text
POST /query
      ↓
ResearchService
      ↓
SemanticRetriever
      ↓
ContextBuilder
      ↓
Ollama / Qwen
      ↓
RAGResponse
      ↓
CitationService
      ↓
CitedRAGResponse
```

Each validated citation resolves to an `EvidenceBlock` selected for the corresponding prompt. The model selects a temporary source key; the application owns the document, page, chunk, and evidence metadata.

See [System Architecture](docs/architecture.md), [End-to-End RAG Pipeline](docs/rag-pipeline.md), [Citation Integrity](docs/citations.md), and [RAG API](docs/api.md).

## API

The local FastAPI application currently exposes:

```text
GET    /health
POST   /documents
GET    /documents
DELETE /documents/{document_id}
POST   /search
POST   /query
```

Run the API locally:

```bash
poetry run uvicorn \
  research_assistant.main:app \
  --app-dir src \
  --host 127.0.0.1 \
  --port 8000
```

Interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

The API is currently designed as a local, single-process development baseline rather than a public multi-user service.

## Local Model Runtime

The generation baseline uses a local Ollama model.

Ensure Ollama is installed and running, then:

```bash
ollama pull qwen3.5:9b
ollama list
```

Model files are managed outside this repository and are not committed to Git.

## Local Documents and Data

The persistent vector store is created under:

```text
data/vector_store/
```

Uploaded PDFs are passed through the ingestion/indexing pipeline and their extracted chunk text and provenance are stored in Qdrant.

The vector-store payload contains source text and metadata, so the local Qdrant data should be treated as potentially private research data rather than as a harmless disposable cache.

Local data, environment files, and model artifacts should remain outside version control.

## Roadmap

**Completed:** project foundation, PDF ingestion, token-aware chunking, local embeddings, persistent vector storage, semantic retrieval, local LLM integration, end-to-end RAG orchestration, citation integrity, and the FastAPI application layer.

**Next:** user interface for document management, research questions, cited answers, source inspection, and retrieval evidence.

**Later:** hybrid retrieval, reranking, formal RAG evaluation, research-specific synthesis, observability, containerisation, and reproducible deployment.

## Design Principles

- **Local first:** keep research documents, vectors, retrieval, and inference local where practical.
- **Preserve provenance:** trace retrieved material and cited evidence back to original pages.
- **Understand before abstracting:** implement inspectable mechanics before high-level RAG frameworks.
- **Separate responsibilities:** parsing, embeddings, storage, retrieval, context construction, generation, citations, application orchestration, and HTTP transport remain explicit boundaries.
- **Bound the context:** allocate evidence within explicit model and output budgets.
- **Treat retrieved text as data:** never promote document content into application instructions.
- **Validate model output:** only application-known source IDs may appear as validated citations.
- **Keep transport thin:** HTTP routes delegate domain work to typed application services.
- **Measure instead of guess:** benchmark retrieval, citation behaviour, grounding, and runtime performance before claiming effectiveness.

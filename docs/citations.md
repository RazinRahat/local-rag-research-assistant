# Citation Integrity

## Purpose

Phase 8 turns Phase 7's internal source labels into validated citations in generated RAG answers. The model is instructed to emit a restricted reference syntax, and the application maps each recognised reference back to an `EvidenceBlock` that actually entered that generation request's context.

The model may propose a source key; **the application owns the source identity and metadata**. Document names, pages, and chunk provenance come from the existing retrieval pipeline, not from claims generated by the language model.

```text
Question
   ↓
Retriever → ContextBuilder → EvidenceBlock[S1, S2, ...]
                            ↓
                    Grounded LLM prompt
                            ↓
                  RAGResponse.answer
                            ↓
                       CitationService
                            │
                 ┌──────────┴───────────┐
                 ▼                      ▼
           parse_citations()     validate_citations()
                 └──────────┬───────────┘
                            ▼
                   CitedRAGResponse
                     ├── rag
                     └── citations
                         ├── references[]
                         └── sources[]
```

## Contract With the Language Model

Each selected context block has a prompt-local source ID such as `S1`, `S2`, or `S3`. The grounding prompt asks the model to cite supported statements with the exact syntax `[S1]`. Multiple sources should be written separately, for example `[S1][S2]`; unprovided IDs must not be invented.

Evidence is delimited before generation, for example:

```text
<SOURCE id="S1" file="paper.pdf" page="3">
Retrieved document text...
</SOURCE>
```

`S1` is **not a permanent database identifier**: it denotes an evidence block selected for one specific prompt. Permanent provenance remains with `document_id`, `chunk_id`, `file_name`, and `page_number` on the underlying `DocumentChunk`.

The model's citation syntax is a request to reference a known source, not a trusted statement about bibliographic metadata.

## Citation Package

```text
src/research_assistant/citations/
├── __init__.py
├── exceptions.py
├── models.py
├── parser.py
├── validator.py
└── service.py
```

The package consumes a completed `RAGResponse`. It does not retrieve documents, construct prompts, or run the language model itself.

## Data Models

**`CitationReference`** represents one recognised inline occurrence. It stores `source_id`, `start_index`, and `end_index`, where the end index is exclusive. These offsets locate the literal reference in the Python answer string and allow a future UI to attach interactions to it.

**`CitationSource`** holds a unique referenced `source_id` and its validated `EvidenceBlock`. A source cited several times has one `CitationSource` but several `CitationReference` occurrences.

**`CitationValidationResult`** contains `references` (all occurrences in answer order) and `sources` (unique cited evidence in first-reference order).

**`CitedRAGResponse`** wraps the original `RAGResponse` and its citation validation result. The original answer, selected evidence, and generation diagnostics are retained.

Example:

```text
Answer:
The model dispenses with recurrence [S1]. This helps parallelisation [S1][S2].

References: S1, S1, S2   (three inline occurrences)
Sources:    S1, S2       (two unique evidence blocks)
```

## Parsing

The initial parser recognises strict inline tokens via:

```python
r"\[(S[1-9]\d*)\]"
```

It extracts source IDs and exact character ranges. It does not treat other bracketed expressions—such as `[x, y]`—as references.

The initial contract intentionally does not normalise variants such as `[Source 1]` or `[S1, S2]`. **Important limitation:** the parser ignores unrecognised formats; it does not necessarily raise an error for every malformed citation-looking string. If a response includes at least one valid reference and one malformed reference, the current validator can accept the valid references without noticing the malformed text. Stricter malformed-reference detection is a possible future enhancement.

## Validation

`validate_citations(answer, evidence, require_citations=True)` constructs a lookup from the **actual selected evidence** and checks recognised references against it.

It validates the following invariants:

1. Duplicate `source_id` values in the supplied evidence are rejected (`DuplicateSourceIdError`).
2. An evidence-backed answer must contain at least one recognised citation when `require_citations=True` (`MissingCitationError`).
3. Every recognised `[S#]` must exist in the supplied evidence (`UnknownCitationError` otherwise).
4. Each source key is mapped to its corresponding trusted `EvidenceBlock`.
5. Repeated inline occurrences are preserved while the unique source list is deduplicated.

For example:

```text
Provided prompt evidence: S1, S2, S3
Generated answer:        Attention removes recurrence [S2].
Validation:              S2 → EvidenceBlock → DocumentChunk → paper/page
```

But:

```text
Provided prompt evidence: S1, S2, S3
Generated answer:        Another finding [S99].
Validation:              UnknownCitationError
```

Only context-selected evidence is passed to validation. A chunk that existed in the wider corpus but was not supplied to this generation call is not automatically an allowable citation.

## Application Boundary

Phase 7 continues to return the uncited/unvalidated `RAGResponse` baseline. Phase 8 adds a separate post-generation operation:

```python
raw_response = rag.ask(question)
cited_response = CitationService().validate(raw_response)
```

The two-step design permits later evaluation to inspect both the model's raw output and the application's validated output. The citation service does not silently rewrite the answer or call the LLM again.

For an explicitly insufficient-evidence response, `CitationService` returns empty `references` and `sources` without requiring a fabricated citation. Phase 7 already bypasses generation when no usable evidence is retrieved.

## Source Rendering and Future UI

A validated `CitationSource` gives the application access to trusted provenance:

```text
[S2]
 └── CitationSource
      └── EvidenceBlock
           ├── retrieval_rank
           ├── score
           └── DocumentChunk
                ├── document_id
                ├── file_name
                ├── page_number
                ├── chunk_id
                └── text
```

A future API/UI can display a source label such as `paper.pdf — p. 3` and expose its stored text, without asking the model to generate filenames or page numbers. A polished citation renderer and interactive source preview are planned for the API/UI phases; Phase 8 establishes the mapping and metadata required to build them.

## What Is and Is Not Guaranteed

| Property | Phase 8 status |
|---|---|
| Recognised `[S#]` occurrences have character offsets | Implemented |
| A recognised reference must map to supplied evidence | Implemented |
| Repeated inline references are preserved | Implemented |
| Cited-source metadata comes from provenance, not the model | Implemented |
| Unknown recognised source IDs are rejected | Implemented |
| Evidence-backed answers with no recognised citations are rejected | Implemented |
| Explicit insufficient-evidence answers may have no citations | Implemented |
| Every malformed citation-like format is detected | Not yet |
| Every factual sentence is cited | Not yet |
| The cited chunk semantically supports the neighbouring claim | Not yet |
| Every generated assertion is faithful to the documents | Not yet |

**Citation identity integrity is not equivalent to citation correctness or answer faithfulness.** A reference can point to a real chunk and still be attached to an unsupported assertion. Claim-to-evidence alignment belongs in the evaluation work.

## Test Strategy

Citation tests use synthetic `EvidenceBlock` and `DocumentChunk` instances rather than real inference. They cover single/multiple/repeated references, character offsets, irrelevant brackets, known/unknown IDs, missing citations, unique-source mapping, and the insufficient-evidence bypass. `CitationService` is also checked against a synthetic `RAGResponse`.

The real smoke test exercises `RAGService.ask(...)` followed by `CitationService.validate(...)` on an indexed research paper. It inspects generated source keys and the mapped file, page, rank, score, and chunk text. A deliberate `[S99]` injection confirms the unknown-ID rejection path.

Passing these tests proves behaviour at the parser/mapping boundary; it is not a numerical evaluation of citation relevance in diverse model responses.

## Privacy and Trust

The citation module works on the evidence already selected by the RAG context builder. It neither uploads source text nor accepts document/page provenance asserted by the model. Retrieved documents remain untrusted source data: instructions inside them must not be promoted to higher-priority application instructions.

## Current Limitations and Next Step

This first implementation has no automatic citation repair, no detection of all malformed formats, no full sentence/claim citation coverage check, and no entailment verification. Those limitations should be measured before adding additional logic.

Phase 9 will expose the existing ingestion, search, generation, and validated citation layers through FastAPI, keeping returned source evidence inspectable for the future UI.
